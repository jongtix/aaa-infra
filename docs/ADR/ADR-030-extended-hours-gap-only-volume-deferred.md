# ADR-030: 미국 시간외(Pre/After-Hours) 수집 — 갭(가격) 중심 축소, 거래량 보류

- **상태**: 승인
- **일자**: 2026-06-25

---

## 맥락

[TECHSPEC §3.7 시간외 데이터 수집 정책](../TECHSPEC.md#37-시간외-데이터-수집-정책)과 `extended_hours` 테이블 설계는 미국 Pre/After-Hours에 대해 **갭(가격)** 과 **비정상 거래량**(`volume_ratio` = 금일 시간외 거래량 / 20영업일 중앙값) 두 축을 ML 피처·"주의 환기" 알림 근거로 정의했다. [PRD §9.4 시간외 알림 정책](../PRD.md#94-시간외-알림-정책)도 "시간외 비정상 거래량 감지 → 주의 환기"를 명시했다.

SPEC 작성에 앞서 후보 무료 소스(yfinance/yahoo, Alpaca Free, Polygon Free)를 실측한 결과, **무료로는 신뢰성 있는 미국 시간외 거래량을 확보할 수 없음**이 확인되었다.

### 확인된 사실 (2026-06-25 실측, AAPL)

1. **yahoo v8 chart (`interval=1m`, `includePrePost=true`)**: 시간외 구간의 **가격(OHLC)은 분 단위로 제공하나 거래량은 구조적으로 0**.
   - PRE(04:00~09:30 ET) 330개 분봉 거래량 전부 0. POST의 유일한 `volume>0`(16:00)은 시간외 거래량이 아니라 정규장 마감 거래량이 첫 분봉에 유입된 것.
   - **라이브 PRE(진행 중)·완료된 과거 PRE 모두 0** → 조회 시점 무관, 구조적 미제공. (`api-specs/yahoo-finance/02-extended-hours.md`)
2. **yahoo v7 quote (`preMarketPrice`·`postMarketPrice` 직접 필드)**: **HTTP 401 Unauthorized** — crumb+cookie 인증 필요, 무인증 차단. 사용 불가.
3. **Alpaca Free (IEX feed)**: 시간외 거래량을 제공하나 ① **IEX는 전체 시장 거래량의 ~2.4%**(실측 비교 12,630 / 535,136 trades)만 커버 → 시간외 대표성 극히 낮음 ② 15분 지연 SIP ③ 무료 티어 시간외 접근 제한 정황.
4. **Polygon Free**: 시간외 분봉 거래량 제공하나 ① **5 req/min** ② 15분 지연 ③ 2년 일봉 제한.
5. Alpaca/Polygon API 키 미보유. 발급해도 위 ③④의 대표성·rate limit 한계는 무료 티어에 상존.

### 추가 발견 — 문서 내부 모순

- TECHSPEC §3.4는 "Pre/After-Hours **1분봉**"으로, §3.7은 "**스냅샷 2~3회/일** (실시간 스트리밍 아님)"으로 기술되어 저장 단위가 불일치했다.
- 갭(가격) 산출에는 세션별 **마지막 가격 스냅샷**만 필요하며 1분봉 시계열 저장은 불필요하다. 국내가 실시간 틱 원본도 보관하지 않는([TECHSPEC §3.6](../TECHSPEC.md#36-데이터-보관-정책)) 설계 일관성과도 §3.7의 "스냅샷"이 부합한다.

## 결정

**미국 시간외 수집을 갭(가격) 중심으로 축소하고, 거래량 기반 설계는 보류한다.**

1. **수집 범위**: collector는 `extended_hours`에 미국 Pre/After-Hours **가격 스냅샷**(세션별 시간외 가격 + 갭 기준 종가)만 적재한다. **시간외 거래량 컬럼을 두지 않는다.**
2. **저장 단위**: 1분봉 시계열이 아닌 **세션별 스냅샷(2~3회/일)**. §3.4의 "1분봉" 표현을 "가격 스냅샷"으로 정정한다.
3. **소스**: yahoo v8 chart(`interval=1m`+`includePrePost=true`) 단일. 호출 시점에 세션 마지막 `close`만 추출한다. 거래량 확보용이던 Alpaca/Polygon Fallback은 도입하지 않는다.
4. **갭 계산 위치**: collector는 가격 원본만 저장하고, 갭 % 계산은 소비측(Phase 2 analyzer / Phase 3 notifier)에서 수행한다.
5. **대상 종목**: 미국 활성 전체 종목 — 여기서 "활성 전체"는 **collector가 watchlist sync로 추적·DB에 보유하는 미국 활성 종목**(`findAllActiveOverseasTradable()`: NYSE/NASDAQ/AMEX ∩ STOCK+ETF ∩ active)을 뜻하며, 미국 상장 전체 우주(~6,000+)가 아니다. 스냅샷은 실시간이 아니므로 이 집합(수백 규모) 전체도 부하가 경미하다.
6. **거래량 기반 설계 보류**: `volume_ratio`·비정상 거래량 알림·최소 거래량 Floor는 PRD/TECHSPEC에서 **보류**로 표기한다(삭제 아님). 한국 시간외 거래량의 수급 피처 활용([TECHSPEC §3.7](../TECHSPEC.md#37-시간외-데이터-수집-정책))은 정규장 배치 경로라 본 결정과 무관하게 유지된다.

## 검토한 대안

### 대안 1: 갭(가격) 중심 축소, 거래량 보류 (채택)

| 항목 | 내용 |
|------|------|
| 장점 | 무료·안정(yahoo 단일, 키 불필요). 갭 피처/알림은 그대로 확보. 1분봉 시계열 미저장으로 설계 일관성·저장 절감 |
| 단점 | 시간외 거래량 이상치 피처 미확보(단, ML 필요성 미실증) |

채택.

### 대안 2: 시간외 수집 전체 보류 — 기각

| 항목 | 내용 |
|------|------|
| 장점 | Phase 2 ML 피처 설계 확정 후 일괄 결정 |
| 단점 | 무료로 즉시 확보 가능한 갭(가격)마저 미루게 됨. 갭은 어닝 갭 등 명확한 신호원 |

기각. 갭은 무료로 안정적으로 얻을 수 있어 미룰 이유가 없다.

### 대안 3: 유료 소스(Polygon/Alpaca 유료, 월 $29~) 도입 — 기각

| 항목 | 내용 |
|------|------|
| 장점 | 신뢰성 있는 시간외 거래량 확보 |
| 단점 | 1인 개인 프로젝트 상시 비용. 시간외 거래량의 ML 기여가 미실증인 단계에서 선투자 부적절 |

기각. 거래량의 ML 필요성이 실증되는 시점에 재검토한다.

## 결과

- `extended_hours` 스키마는 **가격 스냅샷 전용**으로 설계한다(시간외 거래량 컬럼 없음). `session` ENUM('PRE','AFTER') 유지.
- 갭 % 계산은 collector가 아닌 소비측에서 수행한다.
- 수집 대상은 미국 활성 전체 종목, 스냅샷 2~3회/일.
- [PRD §9.4](../PRD.md#94-시간외-알림-정책)와 [TECHSPEC §3.4·§3.7·§7](../TECHSPEC.md#37-시간외-데이터-수집-정책)의 거래량 기반 항목을 "보류(본 ADR 참조)"로 교정한다.
- 명세 `api-specs/yahoo-finance/02-extended-hours.md`를 근거로 SPEC을 작성한다.

**재검토 트리거**: 다음 중 먼저 오는 시점에 이 결정을 재검토한다.

1. analyzer(Phase 2) 모델이 시간외 거래량 이상치 피처를 필요로 함이 실증되는 시점
2. 무료/저비용으로 신뢰성 있는(전체 시장 대표성 있는) 미국 시간외 거래량 소스가 확인되는 시점
3. 프로젝트가 시간외 거래량 기반 알림을 제품 요구로 재확정하는 시점([PRD](../PRD.md) 스코프 변경)
