# ADR-031: analyzer 신호 등급 — 5클래스 직접 출력

- **상태**: **대체됨** — [ADR-033](ADR-033-analyzer-continuous-score-price-bands.md) (2026-07-05, 연속 점수 회귀 + 이산화 계층 + 가격 밴드). 본 ADR의 "STRONG = 크게 움직일 것(수익률 크기)" 의미론과 크기/확신 역할 분리는 ADR-033이 그대로 계승하며, 대체되는 것은 "모델이 5클래스를 직접 출력한다"는 표현 방식 결정이다
- **일자**: 2026-07-04
- **범위**: aaa-analyzer

---

## 맥락

analyzer Phase 2 설계 논의(D-12, confidence 산출 정의) 중, 초기 설계 단계에서 검토됐던 대안이 문서에 남아 있지 않다는 사실이 드러났다. PRD 8.1은 결과만 한 문장으로 명시한다.

> 각 신호에는 confidence (0.0 ~ 1.0) 값이 함께 생성된다. 모델은 5개 등급을 직접 출력하며, STRONG 등급은 더 높은 수익/손실이 예상될 때 부여된다.

"직접 출력하며"라는 표현은 대안의 존재를 전제하지만, 그 대안이 무엇이었는지·왜 기각됐는지는 PRD·TECHSPEC·ADR 어디에도 없었다. 본 ADR은 그 대안과 기각 사유를 지금 시점에 재구성해 기록하고, 5클래스 직접 출력 결정을 공식화한다.

### 검토했던 대안 — 3클래스 + confidence 임계 승격

모델이 `BUY`/`HOLD`/`SELL` 3클래스만 직접 출력하고, confidence가 특정 임계값 이상이면 `STRONG_BUY`/`STRONG_SELL`로 **승격**하는 방식.

---

## 결정

**5클래스(STRONG_BUY, BUY, HOLD, SELL, STRONG_SELL) 직접 출력을 유지한다.** 모델은 5클래스 확률분포를 직접 산출하며, STRONG 등급은 confidence 임계 승격이 아니라 예측 수익률 크기(TECHSPEC 6.1 레이블 경계)로 결정된다.

### 기각 사유 — 두 설계는 STRONG의 의미가 다르다

| | 현행 (5클래스 직접 출력) | 대안 (3클래스 + confidence 승격) |
|---|---|---|
| STRONG의 의미 | **크게 움직일 것** (수익률 크기 — 레이블 경계 소관) | 확실히 움직일 것 (방향 확신 — confidence 소관) |
| 예: 확실한 +3%(작지만 확실) | BUY | STRONG_BUY |
| 예: 불확실한 +15% 가능성 | STRONG_BUY (레이블상) | BUY 또는 HOLD |

원설계 의도는 "크게 움직일 것"이었음을 확인했다(2026-07-04). 3클래스+승격 대안을 채택하면:

- STRONG이 확신의 별명이 되어 `confidence`와 의미가 중복된다.
- "얼마나 크게 움직일 것인가"라는 정보가 시스템 어디에도 남지 않는다.
- notifier Tier 1 알림 조건("STRONG 등급 + 높은 confidence", PRD 9.1)의 취지 — 크고(수익률 규모) + 확실한(방향 확신) 것만 즉시 알림 — 가 "확실하고 + 확실한 것"으로 퇴화한다.

대안의 장점(confidence 산출 시 5클래스 인접 등급 분산 문제가 소멸, STRONG 희소 클래스 제거로 클래스 불균형 완화, STRONG 임계값을 모델 재학습 없이 운영 튜닝 가능)은 인정하나, 그 이득은 이미 confidence 산출식(TECHSPEC 8.5절, ADR 범위 밖)의 **방향별 확률 합** 정의로 대체 확보되어 있다 — 등급이 크기를, confidence가 방향 확신을 각각 전달하는 역할 분리로 두 설계의 장점을 모두 취한다.

---

## 검토한 대안 상세

### 대안 — 3클래스 + confidence 임계 승격 — 기각

| 항목 | 내용 |
|------|------|
| 장점 | confidence 산출식이 예측 클래스 확률만으로 충분(구분 문제 소멸), STRONG 희소 클래스 제거로 SMOTE/class weight 필요성 완화, STRONG 임계값 운영 튜닝 가능(재학습 불요) |
| 단점 | STRONG과 confidence가 "확신"을 중복 표현, 수익률 크기 정보가 시스템에서 소실, Tier 1 알림 취지 퇴화 |

기각. PRD 8.1이 이미 "모델은 5개 등급을 직접 출력"으로 확정한 결론과 일치하며, 크기/확신 역할 분리가 정보 손실 없는 설계로 판단된다.

---

## 결과

- TECHSPEC 6.1의 5클래스 레이블 정의를 그대로 유지한다.
- confidence는 별도로 방향별 확률 합으로 정의한다(TECHSPEC 8.5절).
- 향후 유사한 초기 설계 논의는 기각 대안과 사유를 그 시점에 문서화하여 재소실을 방지한다(analyzer Phase 2 설계 문서 `docs/analyzer-phase2-design-draft.md` D-12 참조).

### 재검토 트리거

- 운영 데이터에서 STRONG 등급의 예측 정확도가 BUY/SELL 대비 유의하게 낮게 관측되고, 원인이 레이블 경계(수익률 크기) 자체의 신뢰도 부족으로 확인될 때
- notifier Tier 1 알림이 "크고 확실한 신호" 취지와 다르게 운영되는 것이 데이터로 확인될 때
